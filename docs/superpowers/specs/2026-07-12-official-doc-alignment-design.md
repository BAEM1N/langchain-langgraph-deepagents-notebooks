# 공식 문서 정합성 개선 설계

## 목표

현재 공식 LangChain·LangGraph·Deep Agents 문서와 충돌하는 교육 내용을 바로잡고, 한국어·영어 노트북과 핸드북 파생본을 함께 동기화한다. 이후 동일한 유형의 회귀를 조기에 발견할 수 있도록 로컬 정적 검사와 선택적 온라인 드리프트 검사를 추가한다.

## 범위

포함한다.

- 확인된 API·행동 계약 불일치 수정
- 영향받는 한국어·영어 노트북 동기화
- 노트북에서 생성되는 Typst 장과 PDF 재생성
- 오래된 공식 문서 링크 교체
- Deep Agents 패치 버전 정렬과 새 `delete` 백엔드 계약 반영
- 공식 문서 핵심 계약을 감시하는 검사 스크립트와 CI 실행 경로

제외한다.

- 241개 노트북의 전면 재작성
- 공식 문서 148개 원문의 저장소 내 복제
- `08_integration/`의 오래된 링크 전체를 이번 변경에서 일괄 교체
- 새 프레임워크나 새 런타임 의존성 추가
- 기본 모델 `gpt-5.4` 정책 변경

## 고려한 접근

### 확인된 오류만 수정

변경량은 가장 작지만 같은 문제가 다른 언어·핸드북·후속 문서에 다시 남을 가능성이 높다.

### 공식 문서 전체 재동기화

누락 가능성은 낮지만 공식 예제의 모델명이나 공급자 예시까지 대량 반영되어 교육 정책과 충돌하고, 검토하기 어려운 큰 diff를 만든다.

### 선택한 접근: 표적 수정과 드리프트 가드 결합

확인된 행동 계약만 수정하고 파생 산출물을 동기화한다. 공식 문서 전체 해시가 아니라 안정적인 핵심 계약과 금지 패턴을 감시하므로 모델 예시 변경 같은 잡음은 실패로 취급하지 않는다.

## 설계 원칙

1. 공식 행동 계약을 우선하고 저장소 고유 정책은 명시적으로 유지한다.
2. 한국어 노트북을 고친 경우 영어 미러와 자동 생성 핸드북도 같은 변경 집합으로 취급한다.
3. 네트워크가 필요한 검사는 기본 로컬 검증과 분리한다.
4. 드리프트 검사는 전체 페이지 해시보다 의미 있는 앵커와 금지 패턴을 검사한다.
5. 패치 버전 업그레이드는 해당 API를 실제로 검증한 뒤 문서에 반영한다.

## 변경 단위

### LangGraph 인터럽트 입력 검증

노드 내부 `while True`에서 `interrupt()`를 반복하는 예제를 제거한다. 노드당 한 번만 인터럽트하고, 잘못된 입력이면 질문을 상태에 저장한 뒤 조건부 엣지로 같은 노드에 재진입한다.

### 에이전트 생성 API

프로덕션 예제의 `langgraph.prebuilt.create_react_agent`를 `langchain.agents.create_agent`로 교체한다. 마이그레이션 설명에 있는 레거시 표기는 허용 목록으로 남긴다.

### HITL 결정 의미

`reject`는 부작용 작업의 거부에 사용하고, `respond`는 사람이 도구 역할을 대신하는 질문형 도구에만 사용한다. 이메일 전송 예제에는 `respond`를 허용하지 않고 별도의 `ask_user` 예제로 네 번째 결정을 시연한다.

### 로컬 셸 보안

`LocalShellBackend(virtual_mode=True)`를 안전 모드나 샌드박스로 표현하지 않는다. `virtual_mode`는 파일 도구 경로 정규화에만 유효하며 셸 명령의 호스트 접근을 막지 못한다는 문장을 최상위 규칙과 학습 자료에 동일하게 반영한다.

### Deep Agents 백엔드 계약

`deepagents` 잠금 버전을 현재 패치 버전으로 올리고 선택적 `delete(file_path) -> DeleteResult` 계약을 문서와 백엔드 노트북에 추가한다. 커스텀 백엔드가 `delete`를 구현하지 않으면 도구가 숨겨진다는 점을 명시한다.

### 공식 문서 링크

코어 경로 `07_examples/01`과 `07_examples/02`의 `python.langchain.com` 링크를 현재 `docs.langchain.com` 경로로 바꾼다. `08_integration/`의 광범위한 링크 마이그레이션은 별도 백로그로 기록한다.

## 드리프트 검사 구조

- `scripts/check_official_docs_alignment.py`
  - `--local`: 저장소 금지 패턴, 링크, 버전, 한·영 대상 존재 여부 검사
  - `--online`: 공식 Markdown 4개를 가져와 핵심 계약 앵커 검사
- `docs/verification/official-docs-watchlist.json`
  - 공식 URL, 필수 앵커, 로컬 대상, 허용 예외를 데이터로 관리
- `tests/test_official_docs_alignment.py`
  - 네트워크 없이 파서와 판정 로직을 fixture 문자열로 검증
- `.github/workflows/official-docs-alignment.yml`
  - PR에서는 로컬 검사만 실행
  - 수동·정기 실행에서는 온라인 검사도 실행

## 성공 기준

- 공식 문서와 충돌한 세 예제가 현재 계약으로 바뀐다.
- `create_react_agent`는 마이그레이션 허용 파일 밖에서 검색되지 않는다.
- `LocalShellBackend`를 샌드박스나 안전 경계로 설명하는 문장이 남지 않는다.
- 한국어·영어 노트북은 JSON, 셀 ID, 코드 길이 규칙을 통과한다.
- 변경 노트북이 로컬 실행 하네스를 통과한다.
- 관련 Typst 장과 한국어·영어 PDF가 다시 빌드된다.
- 로컬 드리프트 검사는 네트워크 없이 통과하고 온라인 검사는 네 개 공식 페이지의 핵심 계약을 확인한다.

## 리스크와 완화

- 공식 문구 변경으로 온라인 검사가 오탐할 수 있다. 정확한 긴 문장 대신 API 이름과 짧은 의미 앵커를 조합한다.
- Deep Agents 패치 업그레이드가 간접 의존성을 바꿀 수 있다. `uv lock --upgrade-package deepagents` diff를 제한적으로 검토하고 변경 노트북을 다시 실행한다.
- Typst 전체 변환이 손으로 다듬은 장을 덮어쓸 수 있다. 변경된 노트북과 대응 장만 위치 인자로 개별 변환한다.
- 한·영 내용이 어긋날 수 있다. 대상 쌍과 핵심 API 토큰을 검사 스크립트에 명시한다.

## 검증 중단 조건

다음 중 하나라도 발생하면 완료로 보고하지 않는다.

- 공식 계약 앵커를 현재 패키지에서 재현할 수 없음
- 변경 노트북 실행 실패
- 한·영 파생 장 불일치
- PDF 빌드 실패
- 예상하지 않은 대규모 `uv.lock` 변경
