## 03. Deep Agents는 '에이전트 앱'이 아니라 장기 작업 하네스입니다

Deep Agents는 '에이전트 앱'이 아니라 장기 작업 하네스입니다. create_deep_agent()는 LangGraph 기반 실행 그래프에 운영에 필요한 미들웨어를 미리 결합합니다. 핵심 레이어는 다음과 같습니다. Planning은 할 일 관리에 해당합니다. 작업을 세부 단계로 나누고 진행 상태를 관리합니다. 코드에서는 write_todos 같은 형태로 드러납니다. Filesystem은 작업 공간에 해당합니다. 파일 읽기·쓰기·편집 도구와 백엔드 추상화를 제공합니다. 코드에서는 StateBackend · FilesystemBackend 같은 형태로 드러납니다. Subagents는 위임에 해당합니다. 컨텍스트를 줄이고 전문 역할에 긴 작업을 나눕니다. 코드에서는 SubAgent · AsyncSubAgent 같은 형태로 드러납니다. Memory & Skills는 축적에 해당합니다. 장기 메모리와 점진적으로 공개되는 스킬 지침을 결합합니다. 코드에서는 CompositeBackend · SKILL.md 같은 형태로 드러납니다. 이 구조를 잡아 두면 뒤에서 API가 늘어나도 같은 기준으로 분류합니다.

## 04. Deep Agents 아키텍처는 LangGraph 위에 planning·filesystem·subagent를 얹습니다

Deep Agents 아키텍처는 LangGraph 위에 planning·filesystem·subagent를 얹습니다. 그림의 각 블록은 이후 노트북에서 코드로 직접 조정하는 표면입니다. 그림은 코드보다 먼저 봐야 할 실행 구조를 압축합니다. 화면에서 Runtime는 LangGraph CompiledStateGraph로 실행됩니다. Middleware는 파일, 메모리, 스킬, 요약, 서브에이전트를 조합합니다. Backends는 상태·파일·스토어·샌드박스를 같은 파일 도구 표면으로 연결합니다. 이 슬라이드는 이름 암기가 아니라, 다음 코드에서 어느 객체가 어떤 역할을 맡는지 미리 잡기 위한 장면입니다.

## 08. 핵심 개념 5가지는 장기 작업 실패를 막기 위한 장치입니다

Planning, context, backend, subagent, memory/skill은 기능 목록이 아니라 실패 원인별 대응책입니다. 묶음별로 읽으면 긴 작업을 끝까지 밀고 가기에서는 Planning은 작업을 세부 단계로 나눕니다; Filesystem은 중간 산출물을 파일로 남깁니다; Context management는 불필요한 대화 누적을 줄입니다를 봅니다. 반복 작업을 안정화하기에서는 Backends는 상태·파일·메모리 저장 경계를 정합니다; Subagents는 전문 작업을 격리합니다; Skills는 절차 지식을 필요할 때 읽게 합니다를 봅니다. 이런 정리 슬라이드는 실습 중 체크리스트로 사용하면 좋습니다. 코드가 동작하는지뿐 아니라, 상태와 권한과 실패 처리를 함께 확인해야 합니다.

## 10. 핵심 개념 5가지는 장기 작업의 실패 원인을 막기 위한 장치입니다

핵심 개념 5가지는 장기 작업의 실패 원인을 막기 위한 장치입니다. 계획 없이 긴 작업을 맡기면 컨텍스트가 부풀고, 파일과 메모리 경계가 흐려집니다. 카드별로 보면 Planning은 긴 작업을 todo 단위로 나누고 진행 상태를 남깁니다. Context Management는 필요한 정보만 유지하고 요약으로 컨텍스트 압박을 줄입니다. ## 226. Deep Agents 실전은 장기 작업을 제품 기능으로 만드는 단계입니다

Deep Agents 실전은 장기 작업을 제품 기능으로 만드는 단계입니다. 기초의 create_agent, 심화의 StateGraph 위에 파일·메모리·스킬·서브에이전트·샌드박스·ACP를 얹어 실전 하네스를 완성합니다. 이 트랙에서 남겨야 할 핵심은 계획, 파일시스템, 메모리, 서브에이전트, 스킬을 묶어 장기 작업 하네스를 설계하는 일입니다. 실습 코드를 모두 외울 필요는 없습니다. 대신 어떤 상황에서 어떤 레이어를 선택하고, 상태와 도구와 권한을 어디에서 관리할지 말로 설명하는 수준까지 가야 합니다. 이 기준으로 다시 노트북을 열어 보면, 각 코드 셀이 단순 예제가 아니라 운영 가능한 에이전트를 구성하는 하나의 결정 지점으로 보입니다.
